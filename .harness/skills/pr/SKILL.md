# 커밋 · PR

## 실행 조건

사용자가 커밋 또는 PR 을 **명시적으로 요청**했을 때만. 머지 · "Merge when ready" · 배포는 이 스킬의 범위가 아니다 (`core.md`).

## 절차

1. **브랜치 확인**: 보호 브랜치(`dev` · `staging` · `main`)면 `core.md` 이름 규칙으로 새 브랜치를 만든다.
2. **변경 확인**: `git status` · `git diff` 로 의도한 파일만 들어가는지 본다. `Secrets*.xcconfig` · 개인 설정(`.claude/settings.local.json`) · 빌드 산출물은 넣지 않는다.
3. **커밋**: `<type>: <한국어 요약>`. 기능 단위로 나누되, `feature → dev` 는 Squash 머지라 커밋 수에 집착하지 않는다. hotfix 는 커밋 1개.
4. **PR 대상**: 기능 · 수정 → `dev`. `hotfix/*` → `main`. 승격(`dev → staging` · `staging → main`)은 사용자가 요청할 때만.
5. **PR 본문** (기존 PR 형식)

   ```
   ## 변경 사항

   ### <묶음 제목>
   - <무엇을 왜>
   (버그면: 증상 · 원인 · 수정)

   ## 테스트
   - <실제로 실행한 명령과 결과. 실행하지 않았으면 그렇게 적는다>
   ```

   UI 변경이면 스크린샷을 첨부해 달라고 사용자에게 알린다.
6. push 후 PR URL 을 보고한다. CI 결과를 기다리거나 큐에 넣지 않는다.

## 완료 조건

- 의도한 변경만 커밋됐다.
- PR 본문의 "테스트" 가 실제 실행 결과와 일치한다.
- 머지 · 큐 추가를 하지 않았다.
