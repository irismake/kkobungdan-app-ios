# 하네스 3단계 — 에이전트 역할 분리

## 역할

| 역할 | 누가 | 하는 일 | 못 하는 일 |
|---|---|---|---|
| 오케스트레이터 · 구현자 | 메인 세션 | 사용자와 대화, 작업 경로 판정, 승인 받기, 구현 · 테스트, reviewer 지적 반영 | 승인 없는 커밋 · 머지 · 배포 (`core.md`) |
| planner | `.harness/agents/planner.md` | L 경로 작업의 요구사항 체크리스트 · 영향 범위 · 적용 규칙 · 구현 순서 · 위험 · 질문 | 파일 수정, 빌드 · 테스트, 프로젝트에 없는 패턴 제안 |
| reviewer | `.harness/agents/reviewer.md` | 변경분을 직접 읽고 요구사항 충족 · 결함 · 규칙 위반을 근거와 함께 보고 | 파일 수정, 근거 없는 지적, 구현자 설명에 의존 |

- 구현자를 별도 에이전트로 두지 않는다. 메인 세션이 이미 사용자 요청 · 대화 맥락을 갖고 있어서, 서브에이전트로 넘기면 같은 컨텍스트를 다시 읽는 비용만 생긴다.
- planner 는 탐색을 별도 컨텍스트에서 하고 요약된 계획만 돌려주므로 메인 세션 컨텍스트를 아낀다.
- reviewer 는 새 컨텍스트에서 요구사항과 기준 ref 만 받는다. 구현 과정을 모르는 상태로 diff 를 읽어서 독립적이다.
- **역할당 에이전트 하나.** 같은 일을 여러 에이전트 · 다른 모델로 중복 실행하지 않는다 (토큰).

## 작업 경로 (`core.md`)

| 경로 | 기준 | 흐름 |
|---|---|---|
| S | 문구 · 스타일 · 한 파일 단순 수정 | 바로 구현 |
| M | 한 계층 안의 기능 · 버그 | 계획 몇 줄 공유 → 구현 |
| L | 여러 계층, 또는 위험 영역 (Network · Token · DIContainer · pbxproj · CI/CD · 서버 계약 · 동시성) | planner → 사용자 승인 → 구현 → reviewer → 반영 → 재검토 1회까지 |

```
사용자 요청 ─▶ 메인 세션: 경로 판정
   S ─▶ 구현
   M ─▶ 계획 공유 ─▶ 구현
   L ─▶ planner(계획) ─▶ 사용자 승인 ─▶ 구현 ─▶ reviewer ─┬─ 통과 ─▶ 보고
                                               ▲          └─ 수정 필요 ─▶ 반영 ─┘ (재검토 1회까지)
```
