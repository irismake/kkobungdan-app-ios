# 하네스 6단계 — 독립 AI 리뷰 · 피드백 루프

## 독립 리뷰

- 리뷰 담당은 3단계의 `reviewer` 하나 (`.harness/agents/reviewer.md`). L 경로 작업과 사용자가 요청할 때 쓴다.
- **독립성**: 요구사항 체크리스트와 비교 기준 ref 만 넘긴다. 구현자의 설명 · 대화는 넘기지 않고, reviewer 가 diff 와 주변 코드를 직접 읽는다. Codex 는 구현한 세션이 아닌 새 세션에서 reviewer 지침을 따른다.
- **지적 처리**: 구현자는 지적마다 "반영 / 반영 안 함(이유)" 로 정리해 사용자에게 보고한다. 재검토는 1회까지 (`core.md`).

## 피드백 루프 (`feedback` 스킬)

```
실수 · 위반 발견 (사용자 지적 · reviewer · 훅 · CI)
  └▶ 로그에서 같은 유형 확인 (재발이면 기존 수단이 왜 못 막았는지)
      └▶ 원인 분류: 규칙 없음 / 강제 없음 / 규칙이 틀림 / 로드 안 됨 / 검사 구멍
          └▶ 수단 선택: ① 결정적 검사 · 훅 > ② 회귀 테스트 > ③ 규칙 문구 · paths > ④ 로그만(사유 필수)
              └▶ 반영 (하네스 변경은 사용자 승인) → 같은 실수를 만들어 실제로 걸리는지 확인 → 로그 기록
```

- 규칙이 실제 코드와 다르면 규칙을 코드에 맞춘다 (코드를 바꿔야 하면 사용자에게 묻는다).
- 로그 `.harness/feedback-log.md` 는 상시 로드하지 않는다. `feedback` 스킬을 쓸 때만 읽는다.
