## 실사용 후 비교할 것

하네스가 dev 에 반영된 뒤 2주 또는 작업 PR 10건 이상이 쌓이면 아래를 실행한다. `--since` 는 dev 반영 시각.

```sh
python3 .harness/metrics/collect_github.py --since <반영 시각>   # PR · CI
python3 .harness/metrics/collect_agents.py --since <반영 시각>   # 토큰 · 작업 시간 + 하네스 검사 기록
```

| 지표 | 기준선 | 기대 | 출처 |
|---|---|---|---|
| CI `Lint` 실패 (CI 에서 처음 잡힌 위반) | 0 (표본 11) | 0 유지 — 로컬에서 먼저 잡힘 | collect_github 실패 job |
| 로컬에서 잡힌 위반 (편집 · 종료 훅 · pre-commit) | 없음 (계측 전) | 기록 시작 | collect_agents 하네스 검사 기록 |
| 실행 전 훅 차단(deny) · 확인(ask) | 없음 | 기록 시작 — deny 가 잦으면 오탐 검토 | 〃 |
| Merge Queue 최초 통과율 | 90% (표본 10) | 유지 또는 상승 | collect_github |
| 작업 1시간당 입력 토큰 (Claude) | 약 30.0M | 감소 | collect_agents |
| PR 당 커밋 수 · 변경 라인 · fix 비율 | 6.5 · 603 · 16.3% | 참고 (작업 성격에 따라 변동) | collect_github |
| 같은 유형 실수 재발 | — | 0 | `.harness/feedback-log.md` 유형 열 |

## 최적화 기준 (이럴 때 손본다)

| 신호 | 조치 |
|---|---|
| 실행 전 훅 deny 가 정상 작업을 자주 막음 | `feedback` 스킬로 기록 → 패턴을 좁힌다 (예: `fastlane` 은 명령 위치만) |
| 종료 훅이 같은 위반으로 계속 막음 | 규칙이 실제 코드와 다른지 확인 → 규칙을 코드에 맞추거나 검사 제외 |
| CI `Lint` 에서 하네스 검사가 처음 실패 | 로컬 단계(훅 · git 훅)가 왜 못 잡았는지 확인 — git 훅 미설치 · `--no-verify` · Codex 작업 등 |
| 상시 로드 토큰이 다시 늘어남 (`core.md` 비대) | 경로로 나눌 수 있는 내용을 `paths` 규칙으로 옮긴다 |
| 같은 유형 실수가 로그에 두 번째로 기록됨 | 기존 수단이 왜 못 막았는지부터 — 더 강한 수단(검사 > 테스트 > 규칙)으로 |

## 한계

- Claude Code 세션 로그는 기본 30일 뒤 삭제된다 (`cleanupPeriodDays`). 비교 기간 데이터가 사라지기 전에 집계하거나 설정을 늘려야 한다 — 개인 설정이라 사용자 결정.
- Codex 는 훅이 없어 "로컬에서 잡힌 위반" 에 Codex 작업은 git pre-commit · verify.sh 분만 들어간다.
- 1인 프로젝트라 표본이 작다. 수치와 함께 피드백 로그 사례로 판단한다.
